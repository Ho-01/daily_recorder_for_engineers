# 주간 요약 카드 (Weekly Summary Card) 설계

**시각화** 탭에서 **일간 1:1 요약 카드**(`DailySummaryCard`)와 나란히 제공할 **이번 주(또는 선택 주) 활동 스냅샷**용 카드. SNS 업로드·회고용 PNG와 동일한 품질 목표를 둔다.

---

## 1. 배경·목표

| 구분 | 설명 |
|------|------|
| 문제 | 일간 카드는 **하루**에 초점이 맞춰져 있어, “이번 주 나의 성장·작업 분포”를 한 장으로 공유하기 어렵다. |
| 목표 | **주 단위**로 로그·유형·카테고리·태그·(선택) 일별 리듬을 압축해 **1:1 비율 카드**로 보여 주고, **PNG 저장**까지 동일 UX로 제공한다. |
| 비목표(MVP) | LLM 자동 요약, 클라우드 공유, 주간 리포트 PDF, 스키마 변경(여전히 소스는 일별 JSON만). |

성공 기준: 사용자가 **한 번의 탭 전환과 주 선택**으로 주간 카드를 보고, **의미 있는 빈 상태 메시지** 없이도 디자인이 깨지지 않는다.

---

## 2. “주(Week)” 정의

혼동을 줄이기 위해 제품 내에서 다음을 **고정**한다.

| 항목 | 결정 |
|------|------|
| 범위 | **월요일 00:00 ~ 일요일**(로컬 타임존, 브라우저/Electron 렌더러의 `Date`와 동일 기준). |
| 라벨 | 카드 상단에 **ISO 주 번호보다 사용자 친화적** 표기를 우선: `2026년 5월 5일 ~ 5월 11일` 형식(연도는 시작·끝이 다르면 둘 다 표기). |
| “이번 주” | 오늘 날짜가 속한 **[월~일] 블록**. |
| 과거/미래 주 | 날짜 피커 또는 **이전 주 / 다음 주** 버튼으로 이동. 미래 구간은 데이터가 없을 수 있음(§7). |

참고: ISO 8601의 “연주 번호”는 연도 경계에서 혼동이 있어 **MVP 라벨에는 사용하지 않는다.** 후속에 설정으로 “ISO 주 표시” 옵션을 둘 수 있다.

---

## 3. 정보 설계 (카드에 무엇을 넣을까)

일간 카드와 **시각적 패밀리**(그라데이션·테두리·1:1)를 맞추되, 영역은 주간 집계에 맞게 조정한다.

### 3.1 필수(MVP)

| 영역 | 내용 | 데이터 소스 |
|------|------|-------------|
| 헤더·브랜드 | 앱/시리즈 이름, **주간 기간 문구** | UI 상태(선택된 주의 월~일) |
| 핵심 지표 행 | **총 로그 수**, **기록된 날 수**(로그 ≥1인 날), **가장 많이 나온 Type 1개**(동률 시 id 순) | 주간 구간 합산 |
| 분포 | Type별 건수 **가로 막대 또는 미니 막대 그리드**(일간 카드의 meta 느낌과 통일) | 동일 |
| 상위 태그·카테고리 | 각각 **상위 N개**(일간 카드와 동일 N 또는 주간만 6~8) | 동일 |
| 푸터 한 줄 | 주간을 한 줄로 압축한 **비공식 요약**(선택, §5.2) 또는 고정 카피 | 계산 또는 생략 |

### 3.2 선택(Phase 2 이후)

| 영역 | 설명 |
|------|------|
| 미니 **주간 히트맵** | 7칸(월~일) 또는 7×1 막대, 일별 `logCount` 색 농도 — 일간 카드의 `cardInsights.heatmap`과 역할이 겹치므로 **주 전용으로 단순화**. |
| **저널 스니펫** | 해당 주에 `journal` 문자열이 비어 있지 않은 날만 모아 bullet **최대 2~3줄**(잘림 처리). 전체 텍스트는 비저장·표시만. |
| **연속 기록** | 일간 카드의 “스트릭”과 다른 의미로, “이번 주 중 며칠 연속으로 로그가 있었는지” 등(과하면 스킵). |

## 4. 데이터·IPC 전략 (스키마 변경 없음)

저장 형식은 [DATA_SCHEMA.md](../DATA_SCHEMA.md) 그대로. 주간 카드는 **여러 일별 파일을 읽어 집계한 뷰**일 뿐이다.

### 4.1 이미 있는 API

- **`aggregateRange(from, to)`** (`AggregateRangeResult`): 일별 `logCount`, `typeCounts`, `categoryCounts`, `tagCounts`가 들어 있다. **주간 구간만 넘기면** 대부분의 막대·상위 리스트를 만들 수 있다.

### 4.2 렌더러에서 보완 가능한 부분

- **기록된 날 수**: `aggregate.days`에서 `logCount > 0`인 날만 카운트.
- **저널 스니펫(후속)**: 해당 주의 각 날짜에 대해 `readDaily(iso)`를 호출하면 된다. IPC 호출이 많아지므로 **Phase 2**로 미루거나, main에 **`readDailyRange`** 한 방 invoke를 추가하는 편이 낫다(§8).

### 4.3 새 IPC가 가치 있는 시점

다음 중 하나라도 MVP에 넣으면 **`weeklyCardInsights(from, to)`** 같은 **단일 invoke**를 권장한다.

- 저널 요약 한 줄을 **main에서** 안전하게 잘라 합치기.
- 스트릭·연속 일수 등 **여러 파일 순회**를 한 번에 하고 싶을 때.

페이로드는 기존 `shared/visualization.ts` 스타일로 타입을 두고, 구현 후 [DEVELOPMENT_GUIDE.md](../DEVELOPMENT_GUIDE.md) IPC 표에 추가한다.

## 5. UI·화면 배치

### 5.1 시각화 탭 구조

현재: 하위 탭 **요약 카드** | **기간 차트**.

변경안:

- **요약 카드** 안에서 다시 세분화: **`일간` | `주간`** (세그먼트 컨트롤 또는 소제목 탭).
- 또는 최상위를 **일간 카드 | 주간 카드 | 기간 차트** 세 탭으로 확장.

**권장:** 첫 번째(요약 카드 내부 일간/주간) — “카드 계열” UX가 한 덩어리로 유지된다.

### 5.2 레이아웃·CSS

- **1:1 비율**, `--summary-card-w`와 동일 계열 폭(일간과 나란히 비교했을 때 이질감 최소화).
- 컴포넌트 후보 이름: `WeeklySummaryCard.tsx`.
- 캡처 루트는 일간과 동일하게 `ref` + `html2canvas`, **PNG 파일명**: `weekly_YYYY-MM-DD_to_YYYY-MM-DD_card.png` (시작·끝 월요일·일요일).

### 5.3 접근성

- 주 선택 컨트롤에 **레이블**, 카드 영역에 **주간 기간을 읽어 줄 수 있는 구조**(스크린 리더).

## 6. 구현 단계 (로드맵)

| 단계 | 내용 | 산출물 |
|------|------|--------|
| **MVP-A** | 주 범위 계산 유틸(월~일), `aggregateRange`로 주간 데이터 로드, `WeeklySummaryCard` 정적 레이아웃 + 상위 Type·Category·Tag | 탭·카드 표시 |
| **MVP-B** | PNG 저장, 빈 주·부분 주 처리, 로딩·에러 상태 | 일간 카드와 동등한 저장 UX |
| **Phase 2** | 저널 스니펫 또는 `readDailyRange` / `weeklyCardInsights` | 카드 정보 밀도 증가 |
| **Phase 3** | 미니 7일 히트맵, ISO 주 옵션, 테마 토글 | 차별화 |

---

## 7. 빈 상태·경계 조건

| 상황 | 동작 |
|------|------|
| 해당 주 **어떤 날짜도 파일 없음** 또는 로그 합계 0 | 일간 카드와 톤을 맞춘 **빈 상태 일러스트/카피**: “이번 주 기록이 없습니다” + 기간은 그대로 표시. |
| 주 **일부 날만** 파일 존재 | 있는 날만 집계; “기록된 날 수”가 자연스럽게 줄어듦. |
| **미래 주** 선택 | 데이터 없음과 동일 처리 또는 다음 주 버튼 비활성화(구현 시 하나로 통일). |

## 9. 오픈 이슈 (결정 보류)

1. **주 시작을 일요일로 할지** — 현재는 **월요일 고정**. 글로벌 사용자 설정은 후속.
2. **일간 카드의 `cardInsights`(스트릭·35일 히트맵)** 를 주간 화면에 얼마나 노출할지 — 정보 과부하 시 제외.
3. **다크 모드만** 할지 — 일간 카드와 동일하게 단일 테마로 시작.

이 문서는 구현을 시작할 때 **§6 MVP-A**부터 코드에 옮기고, UX 시연 후 §3.2·§9를 조정하면 된다.
