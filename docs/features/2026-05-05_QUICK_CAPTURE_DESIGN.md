# 빠른 캡처 / 인박스 모드 설계

로그 한 건을 **최소 마찰**로 오늘 날짜 일일 파일에 붙이는 모드. 본 문서는 구현 전 **요구사항·아키텍처·데이터·IPC·위험**을 고정한다.

---

## 1. 목표

| 목표 | 설명 |
|------|------|
| 생산성 | Daily 전체 화면을 열지 않고 **한두 번 클릭·입력**으로 로그 추가 |
| 성장 흐름 | “기록을 남긴다”는 행동 자체의 비용을 낮춰 **연속 기록·회고**와 연결 |
| 데이터 일관성 | 기존 `LogEntry`·`YYYY-MM-DD_daily.json` 계약 유지 ([DATA_SCHEMA.md](../DATA_SCHEMA.md)) |

비목표(MVP): 풀 텍스트 검색, 클라우드 동기화, LLM 요약.

---

## 2. 사용자 경험(UX)

### 2.1 진입·종료

- 사용자가 **“빠른 캡처 모드”**를 켜면:
  - **메인 창은 보이지 않게** 한다 (아래 3.2절 기술적 선택).
  - **플로팅 캡처 창**만 남기되, 동작은 아래 **§2.4** (접힘/펼침·트레이·작업 표시줄)를 따른다.
- 모드를 끄면: 플로팅 UI·트레이 정리 후 **메인 창을 다시 표시**한다.

### 2.4 플로팅 핸들 · 접힘/펼침 · 디스코드형 백그라운드 (확정 UX)

**목표:** 작업 중에는 방해 최소화, 필요할 때만 작은 입력 폼을 펼친다. 앱은 종료되지 않고 **백그라운드에서 계속 떠 있는 느낌**(Discord와 유사).

| 요소 | 동작 |
|------|------|
| **작업 표시줄** | 빠른 캡처 모드에서 플로팅 창은 **작업 표시줄에 탭으로 나타나지 않게** 한다(Electron: `setSkipTaskbar(true)`). 사용자 입장에서는 “창이 작업 표시줄에서 사라짐”. |
| **트레이(알림 영역)** | 동일 앱이 **백그라운드로 살아 있음**을 알리기 위해 **트레이 아이콘**을 띄운다. “숨겨진 아이콘 표시”로 올리면 아이콘이 보이며, Discord처럼 거기서 앱이 살아 있는 느낌을 준다. |
| **Sticky + 드래그** | 플로팅 UI는 **모니터 가장자리에 붙여 두듯** 기본 배치하되, 사용자가 **드래그해 위치를 옮길 수 있다**. (구현: 드래그 핸들 영역에 `-webkit-app-region: drag`, 버튼·입력에는 `no-drag`.) |
| **접힘 상태** | **작은 버튼(핸들)** 만 보이는 최소 크기. 다른 창을 가리지 않도록 한쪽에 붙여 둔다. |
| **펼침 상태** | 핸들을 누르면 같은 창이 **세로(또는 가로)로 커지며** 빠른 캡처 폼(상세 입력·저장 등)이 나타난다. 다시 접거나 동일 버튼으로 축소 가능. |
| **트레이 메뉴(안)** | 우클릭: 메인 창 열기 · 캡처 창 포커스/펼치기 · 종료 등. 구현 시 조합 결정. |

**창 크기:** 접힘 시 예: 정사각형 소형(예: 44~56px), 펼침 시 기존안처럼 폭 320~400px × 입력에 맞는 높이. Main 프로세스에서 `setSize`/`setBounds`로 동기화하거나, 렌더러에서 레이아웃 분기 후 한 번에 크기 IPC 호출.

**위치 기억(후속):** `userData`에 마지막 `x,y` 및 접힘/펼침 상태 저장 시 재실행 시 복원 가능.

### 2.2 캡처 패널 동작(MVP)

1. 기본 타깃 날짜: **오늘**(로컬 `YYYY-MM-DD`). (후속: 어제/날짜 선택.)
2. 입력: 최소 **상세 텍스트(`detail`)** 한 필드.
3. 저장 시: 해당 날짜 `daily` 파일에 **새 `LogEntry` 한 줄 추가**.
4. 성공 피드백: 짧은 토스트 또는 버튼 상태 변경 후 입력창 비우기.

### 2.3 MVP 이후(비우고 설계만)

- 기본 **유형(`type`)**: 설정 또는 `types.jsonl` 첫 항목 / 마지막 사용값.
- **태그·카테고리**: 최소 선택 UI 또는 생략 후 Daily에서 보완.
- **전역 단축키**: 예) `Ctrl+Shift+L` 로 플로팅 창 포커스 또는 펼침.

## 3. 아키텍처(Electron)

### 3.1 원칙

- 렌더러는 **preload 노출 API만** 사용 ([DEVELOPMENT_GUIDE.md](../DEVELOPMENT_GUIDE.md)).
- 파일 읽기·쓰기·`logId` 생성은 **main**에서 처리하는 편이 안전(경합 한 곳에서 처리).

### 3.2 메인 창 처리 방식 (권장 vs 주의)

| 방안 | 동작 | 장점 | 주의 |
|------|------|------|------|
| **A. 메인 숨김 (`hide`)** | 메인 `BrowserWindow.hide()`, 캡처만 표시 | `window-all-closed`로 앱이 안 끊기기 쉬움 | “닫힘”과 UX 문구 맞추기 |
| **B. 메인 닫기 (`close`)** | 메인만 destroy | 사용자 표현과 일치 | **남는 창 0이면 Windows에서 앱 종료** 가능 → `window-all-closed`에서 캡처 창이 있으면 `quit` 안 하기 등 **반드시 예외 처리** |

**권장:** 구현 단계에서는 **A(숨김)** 로 두고, 사용자에게는 “메인 화면은 접어 두고 캡처만 남긴다”고 안내. 진짜 `close`가 필요하면 B와 함께 앱 종료 로직을 설계한다.

### 3.3 캡처 UI를 어디에 둘지

| 방안 | 설명 |
|------|------|
| **별도 `BrowserWindow`** (권장) | 작은 프레임리스·고정 크기, `loadURL`/`loadFile`로 렌더러 라우트 `#/quick-capture` 등만 표시. 메인과 **동일 preload** 공유 가능. |
| 단일 창 내 오버레이 | 메인을 “닫는다”와 모순되기 쉬움 — 본 요구와 맞지 않음. |

캡처 창 속성(제안):

- `frame: false` — 플로팅 핸들·펼침 UI는 커스텀 타이틀바 없이 렌더러에서 구성.
- **`skipTaskbar: true`** — §2.4: 작업 표시줄에서 숨김.
- `alwaysOnTop: false` (기본); “항상 위” 옵션은 설정으로만.
- 위치: 최초 `screen` API로 우하단; 이후 사용자 드래그(§2.4).
- 접힘/펼침에 따라 **동적 크기** — `setMinimumSize` / `setContentSize` 또는 IPC로 bounds 조정.
- `transparent: false`(기본); 배경은 불투명 권장(클릭 타겟 명확).

### 3.4 트레이 · 앱 종료 정책

- **Main**에서 `Tray` 생성: 아이콘은 `public/` 또는 빌드 리소스에 PNG/ICO(Windows는 여러 해상도 권장).
- **모든 창이 닫혀도** 트레이만 남기면 Windows에서 앱을 유지하려면: `window-all-closed`에서 **트레이가 있으면 `quit` 하지 않음**(플랫폼별로 Discord 등과 동일 패턴).
- 트레이 **“종료”** 시에만 `app.quit()` 호출.
- 빠른 캡처 모드 진입 시: 메인 `hide` + 플로팅 창 `show`; 트레이는 이미 표시되거나 이 시점에 표시.

### 3.5 빌드·라우팅

- **electron-vite**: 렌더러는 단일 `index.html` 유지, React Router 등으로 `/quick-capture` 분기 가능.
- 또는 hash 라우팅 `#/quick-capture` 로 메인 번들 하나에서 처리.
- 플로팅 창은 **같은 렌더러 엔트리**에서 라우트만 분리하는 편이 preload·번들 공유에 유리.

## 4. 데이터 모델·저장

### 4.1 스키마 변경

- **변경 없음.** 새 로그는 기존 `LogEntry` 그대로.

### 4.2 `logId` 발급

- 규칙은 Daily 페이지와 동일: `log_YYYYMMDD_###`, 해당 일 파일 내 유일.
- **main** IPC 한 번의 트랜잭션에서: 해당 일 `daily` 로드 → `nextLogId` 규칙으로 id 생성 → 배열 append → 저장 — 로드·저장 사이에 다른 창이 저장하면 덮어쓰기 위험이 있으므로 **원자적 업데이트** 권장 (아래 4.4).

### 4.3 새 로그 기본값

| 필드 | MVP 기본값 |
|------|------------|
| `type` | `types[0].typeId` 또는 사용자 설정(후속) |
| `categoryIds` | `[]` |
| `tagIds` | `[]` |
| `detail` | 사용자 입력 문자열 |

### 4.4 경합(Race)

시나리오: Daily 페이지(메인)와 캡처 창이 **동시에 같은 날짜 파일** 저장.

- **권장:** main에 `appendLogToDaily(isoDate, partialLog)` 같은 핸들러를 두고, 내부에서 **파일 읽기 → 로그 추가 → 원자적 저장**을 직렬화(단일 큐 또는 동일 날짜 락).
- 최소 구현: 동일 핸들러에서만 오늘 파일 갱신하고, 저장 실패 시 사용자에게 재시도.

## 5. IPC 설계(안)

`src/shared/ipc.ts`에 채널 추가 시 main·preload·renderer **동시 갱신**.

| 채널(제안명) | 방향 | 페이로드 | 설명 |
|--------------|------|----------|------|
| `journal:appendLog` | invoke | `{ isoDate, detail, typeId?, categoryIds?, tagIds? }` | 해당 일 파일에 로그 1건 추가 후 저장 |
| `capture:closeAndShowMain` | invoke | 없음 | 플로팅·트레이 정리 후 메인 표시 (이름은 구현 시 통일) |
| `capture:setPanelBounds`(안) | invoke | `{ width, height }` 또는 `collapsed \| expanded` | 접힘/펼침에 맞춰 창 크기 조정(선택) |

창 제어는 **main 전용**으로 두는 것이 안전:

- `mainWindow.show()` / `captureWindow.close()` 등은 IPC로만 호출.

preload에는 기존 `readTypes` 등과 함께 **`appendLog`** 만 노출해도 MVP 충분.

## 6. UI 컴포넌트(렌더러)

제안 디렉터리:

```text
src/renderer/src/
  pages/QuickCapturePage.tsx    # 플로팅 전용 라우트: 접힘 핸들 + 펼침 폼
  components/QuickCaptureFloatingShell.tsx  # 선택: 레이아웃 분리
  services/journalApi.ts        # appendLog 래퍼 추가
```

- **접힘:** 단일 **드래그 가능한 작은 버튼**(또는 아이콘 버튼). 클릭 시 펼침.
- **펼침:** 폭 320~400px 등, 상세 입력 + 저장 + (후속) 접기 버튼.
- 드래그 영역과 클릭 가능 영역 분리: Electron 문서의 `-webkit-app-region: drag` / `no-drag` 패턴 준수.
- 접근성: 펼침 상태에서 입력·저장에 레이블; 접힘 상태에서 버튼에 `aria-expanded` 연동.

## 8. 테스트·검증 체크리스트(구현 후)

- [ ] 긴 `detail` 저장 후 Daily 페이지에서 동일 파일 열림·로그 표시
- [ ] 메인 숨김 후 플로팅만 남았을 때 앱이 **의도치 않게 종료되지 않음**(트레이·`window-all-closed` 정책)
- [ ] 작업 표시줄에 플로팅 창이 **나타나지 않음**(`skipTaskbar`)
- [ ] 트레이 아이콘 표시·우클릭 메뉴·종료 시 앱 완전 종료
- [ ] 접힘 ↔ 펼침 크기 전환 시 깜빡임·위치 어긋남 최소화
- [ ] 캡처 종료 후 메인 복귀 시 포커스 정상
- [ ] 오늘 파일이 없을 때 빈 템플릿과 동일하게 생성되는지 (`emptyDaily` + todos `[]`)

## 10. 구현 순서 제안

1. **Main:** `journal:appendLog` + 원자적 읽기·추가·쓰기 + `logId` 생성 재사용.
2. **Preload / journalApi:** 래퍼 추가.
3. **플로팅 `BrowserWindow`**: `skipTaskbar`, 프레임리스, 초기 우하단·드래그 가능.
4. **Tray** + `window-all-closed` 시 트레이 유지 시 앱 종료 안 함.
5. **QuickCapture** UI: 접힘 핸들 → 펼침 폼 + 저장.
6. 메인에서 모드 진입/종료 IPC.
7. (후속) 위치 저장·단축키·기본 타입 설정.

이 순서로 진행하면 데이터 레이어가 먼저 안정되어 UI 연동 리스크가 줄어든다.
